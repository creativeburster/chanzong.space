# 禅宗知识库 (chanzong.space) 项目指南与全局规范

欢迎来到 **禅宗知识库 (chanzong.space)** 项目！本文件为全站开发、数据建库、UI设计与内容解惑的全局约束与指导规范。任何 Agent 在该项目下工作时，必须严格遵守以下原则。

---

## 🎯 一、 项目定位与长期战略愿景 (模式 B 战略)

1. **宏大长远眼光**：
   - 当前收集的种子典籍仅占长期目标的 **<1%**。
   - 本站点旨在构建涵盖中国、印度、朝韩、日本及欧美各大禅派的全球化**海量禅宗知识网络体系**。
   - **目标规模**：1,000+ 禅宗典籍、5,000+ 公案机锋问答、500+ 核心概念、100+ 历代祖师。
2. **统一命名规范**：
   - **站点官方名称**：统一使用 **"禅宗知识库"**（ChanZong Knowledge Base / chanzong.space）。
   - **⚠️ 绝对禁忌**：切勿将站点命名为"禅宗正法知识库"或"正法心传"，《正法心传》仅为第一本种子汇编 PDF 的书名。

## 🎨 二、 设计美学与 UI/UX 架构哲学

整体视觉与交互体验严格参照 `ramanamaharshi.space` 站点标准：

1. **色彩与布局格局**：
   - **左侧边栏 (`Sidebar.tsx`)**：深色夜空卡片风格 (`bg-[#0F172A]`)，包含大号粗体导航、缩进子菜单、数量 Badge 统计及快捷 Ctrl+K 搜索。
   - **顶部导航栏 (`TopHeader.tsx`)**：包含大号导航链接（首页 | 书籍 | 概念 | 法门 | 公案 | 人物 | 图谱）与 `[ 简 / 繁 ]` 实时语言切换按钮。
   - **主工作区 Canvas**：温润柔和宣纸画布背景 (`bg-[#FAF9F6]`)。
2. **多卡片交叉互链网络 (Card Interlinking)**：
   - 任何详情页（祖师 `/persons/[id]`、概念 `/concepts/[id]`、法门 `/methods/[id]`、公案 `/qas/[id]`）**不得留白**，必须拆解为多个视觉卡片。
   - 页面底部与侧边必须包含 **交叉引用卡片/胶囊标签**：`相关概念`、`相关祖师`、`相关经典`、`相关法门`，形成全网状相互链接。
3. **D3.js 交互式知识图谱 (`GraphCanvas.tsx`)**：
   - 使用 D3.js v7 SVG 渲染，节点包含【中心正法】、【祖师人物】、【核心经典】、【核心概念】、【修持法门】、【公案问答】（配色 方案：`colorMap`）。
   - 支持节点点击跳转路由、悬浮 Tooltip、邻域高亮与蜘蛛网放射线特效，仿真 3 秒后自动冻结防抖。
4. **PWA 与离线支持 (`PWAInstallBanner.tsx`, `sw.js`)**：
   - 必须保持 PWA Manifest 与 Service Worker 离线缓存支持。
   - **安装提示 Banner 约束**：用户访问 2 分钟后才优雅提示安装，禁止首屏弹出打扰。

## 📚 三、 典籍加工与白话导读规范

1. **彻底去水印与噪点**：
   - 必须清洗原始 OCR 中的页眉（如 `正法心传`、`六祖法宝坛经`）与独立页码（如 `.12·`）。
   - 修正错别字（如将 `涅繁` 修正为 `涅槃`）。
2. **定制白话导读与核心旨趣**：
   - 每部典籍开头必须包含 **【💡 现代白话导读与核心旨趣】**。
   - 导读必须针对该典籍独家撰写（禁止使用通用套话），阐明作者背景、核心宗风与参修意义。

## 🛠️ 四、 技术栈与构建规范

- **框架**：Next.js 14 (App Router) + React 18 + TypeScript + Tailwind CSS
- **数据层**：`lib/taxonomy.ts`（包含全量强类型结构化数据与交叉引用 ID 数组）与 `manifest.json`
- **构建测试**：在修改任何代码后，运行 `npx tsc --noEmit` 确保 exit code 0 且无报错。完整构建用 `node node_modules/next/dist/bin/next build`。

## 📖 五、 禅宗经典发布完整流程（SOP）

当用户提供一部新的禅宗 PDF/TXT 源文本时，"发布"一部经典意味着完成以下 **全部 7 个步骤**，缺一不可：

### 步骤 1：源文本获取与深度理解
- 读取 PDF/TXT 源文本（PDF 需 OCR 或在线搜索获取全文）
- 确认版权：公有领域（作者逝世超过 50 年）方可使用
- 深度理解内容：作者背景、核心宗风、历史地位、修行要旨

### 步骤 2：创建 Markdown 文件 → `classics_markdown/{idx}_{id}.md`
- 文件名格式：`{两位序号}_{拼音id}.md`，如 `39_bashiguijusong.md`
- 必须包含以下结构：
  - `## 💡 现代白话导读与核心旨趣` — 针对该典籍独家撰写
  - `## 📌 关键词` — 3-6 个核心术语
  - `## 🎯 主旨` — 一段话概括
  - `## 📖 重点内容` — 分段提炼
  - `## ⚠️ 阅读难点` — 常见误解与难点
  - `## 🗣️ 名句白话解读` — 核心偈颂/语句的白话
  - `## 📜 典籍原文` — 清洗后的完整原文

### 步骤 3：更新 `manifest.json`
- 在 JSON 数组末尾追加元数据对象：
```json
{
  "idx": 39,
  "id": "bashiguijusong",
  "title": "八识规矩颂",
  "author": "玄奘",
  "category": "唯识宗典",
  "summary": "一句话概括",
  "word_count": 576,
  "filename": "39_bashiguijusong.md"
}
```

### 步骤 4：更新 `lib/translations.ts` — 白话翻译
- 为该经典添加白话译文条目，按段落/偈颂分条
- 数据结构遵循文件中已有格式（`id` 对应 manifest 中的 `id`）

### 步骤 5：更新 `lib/glossary.ts` — 字词注音
- 为该经典中的生僻字词添加注音释义
- 数据结构遵循文件中已有格式

### 步骤 6：更新 `lib/taxonomy.ts` — 扩充知识网络
这是最核心的步骤，需要扩充以下 **全部 5 个数组**（如该经典涉及）：

1. **`ZEN_PERSONS`（人物）**：
   - 若经典作者/主角尚不存在，新增人物条目
   - 若已存在，更新其 `relatedBooks`、`relatedConcepts`、`classics` 等字段，加入新经典 id
   - 字段：`id`, `name`, `title`, `era`, `lifeStory`, `teachings`, `quotes`, `classics`, `relatedConcepts`, `relatedMethods`, `relatedPersons`, `relatedBooks`

2. **`ZEN_CONCEPTS`（概念）**：
   - 新增该经典引入的核心概念（如唯识学"末那识"、禅宗"无门"等）
   - **注意查重**：新增前必须搜索 `id` 是否已存在，避免重复条目
   - 若概念已存在，更新其 `relatedBooks` 加入新经典 id
   - 字段：`id`, `title`, `category`, `summary`, `etymology`, `quotes`, `guidance`, `classicRef`, `relatedConcepts`, `relatedPersons`, `relatedBooks`

3. **`ZEN_METHODS`（法门）**：
   - 若该经典引入新的修行法门，新增法门条目
   - 若已有法门与该经典相关，更新其 `relatedBooks` 和 `relatedPersons`
   - 字段：`id`, `title`, `summary`, `origin`, `steps`, `pitfalls`, `classicRef`, `relatedConcepts`, `relatedPersons`, `relatedBooks`

4. **`ZEN_KOANS`（公案）**：
   - 若该经典包含公案，精选重要公案新增条目
   - 编号续接现有最大编号（如当前最大 koan-205，则从 koan-206 开始）
   - 字段：`id`, `question`, `answer`, `context`, `interpretation`, `master`, `source`, `relatedConcepts`, `relatedPersons`, `relatedBooks`

5. **`ZEN_FAQS`（问答）**：
   - 新增与该经典相关的常见问题及解答
   - 编号续接现有最大编号（如当前最大 faq-308，则从 faq-309 开始）
   - 字段：`id`, `question`, `answer`, `relatedQa`, `relatedBooks`

### 步骤 7：编译验证
- 运行 `npx tsc --noEmit` 确保零错误
- 若有 lint 错误，优先检查字符串中的中文引号转义问题

## 🔗 六、 数据交叉引用规范

### ID 命名规则
- **人物**：拼音连字符，如 `wumen-huikai`、`xuanzang`
- **概念**：拼音连字符，如 `zhuan-shi-cheng-zhi`、`mo-na-shi`
- **法门**：拼音或英文，如 `kanhuatou`、`wumen`
- **公案**：`koan-{编号}`，如 `koan-201`
- **FAQ**：`faq-{编号}`，如 `faq-301`
- **经典**：拼音 id，与 `manifest.json` 中的 `id` 一致，如 `bashiguijusong`、`wumenguan`

### 交叉引用要求
- 每个条目的 `relatedBooks` 必须包含对应的经典 id
- 每个条目的 `relatedPersons` 必须引用已存在的人物 id
- 每个条目的 `relatedConcepts` 必须引用已存在的概念 id
- **禁止悬空引用**：所有引用的 id 必须在对应数组中存在

### TypeScript 字符串转义
- 中文字符串中使用 `\u201c`（"）和 `\u201d`（"）代替直引号
- 避免在字符串中使用未转义的双引号

## 🧠 八、 唯识学与禅宗的关系

唯识学虽为独立宗派，但与禅宗修行密切相关：
- **末那识**（第七识）是一切俱生我执的根源——禅宗参"念佛是谁"正是直探末那识
- **阿赖耶识**（第八识）含藏一切种子——参禅至极处须透过此识方见本来面目
- **转识成智**——禅宗之"悟"本质上即是转识成智：一念迷即八识，一念悟即四智
- **四智**（大圆镜智、平等性智、妙观察智、成所作智）——六祖坛经中已有阐述

因此，《八识规矩颂》等唯识学典籍可作为禅宗修行的理论参考，已纳入本知识库。

## 🛡️ 十、 社区外链人机协同与防封号铁律

1. **严禁在自己主帖下自评自回复**：严禁在自身账号发布的主帖、书评、专栏或动态下进行自问自答或自称“楼主”的自回复，所有互动必须 100% 定向到外部学者、大 V 或独立同修的公开内容下。
2. **验证码立即求助，严禁无头盲破**：无头浏览器极易被平台的 Canvas/WebGL/事件行为指纹识别并触发验证码（图形点选/滑块）。一旦遇到验证页面，必须立即截图并在对话中向用户求助，由用户人工协助过验证，绝对禁止脚本自动化强行盲点，确保账号安全防封第一！

3. **外链形式的三级优雅降级策略**：
   - Tier 1 原生锚文本：掘金、豆瓣、知乎专栏等支持富文本的平台优先生成原生天蓝超链接；
   - Tier 2 完整 https 链接：微博、CSDN 评论等自动识别 URL 平台保留协议头；
   - Tier 3 自然品牌词去协议头：博客园、知乎回答评论、B 站视频评论等严格风控区坚决移除 `https://`，使用【禅宗知识库（chanzong.space）】确保 100% 存活。
4. **Windows Session 0 隔离与 CDP 穿透协同**：后台无头自动化遇高强风控时，通过 CDP 协议连接用户桌面 Edge（`--remote-debugging-port=9222`），机械劳动（输入/排版/DOM/总账）100% 由 AI 承担，用户仅协同拖动滑块验证。
5. **🛑 彻底杜绝机器人模板感与多尺度字数差异化铁律**：严禁各平台（尤其是 B 站、微博、知乎）发布的动态或文章字数、句式与格式高度趋同（如清一色 150 字三段式模板），这极易被平台风控算法和人类读者识别为流水线机器人。必须严格构建三级长短尺度阶梯（短篇 80~140 字即兴觉照随感、中篇 260~420 字心性与生活札记、长篇 600~1000+ 字典籍公案全景深度解密），排版句式随文而化，呈现富有生命力的人文质感。
6. **🎯 媒体垂直相关性优先与技术社区低频轻量化铁律（2026-09-11 确立）**：
   - **核心宗风与受众契合**：本站为“禅宗知识库 (chanzong.space)”，核心价值在东方心性哲学、国学经典考据、生活禅疗愈与公案义理。
   - **核心垂直阵地（≥85% 权重）**：外链建设的主力阵地聚焦在具备强话题垂直相关度、受众粘性高且自动化友好的三大国民级平台：**知乎 (Zhihu DA 95+)**、**新浪微博 (Weibo DA 90+)**、**哔哩哔哩 (Bilibili DA 94+)** 及海外学术分发平台（Telegraph / Rentry）。注：小红书网页端风控繁琐且体验较差，已永久排除，不予投入精力。
